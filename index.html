Key decisionsDecisiones clave

  1. 01Intent first, not method firstPrimero la intención, no el métodoClients want to upload a file, not learn four methods and their caveats. One entry point replaced the choice of channel.Los clientes quieren subir un archivo, no aprender cuatro métodos y sus letras pequeñas. Una sola entrada reemplazó la elección de canal.
  2. 02One lifecycle for every channelUn ciclo de vida para todos los canalesInstead of designing each service as its own feature, I designed the stages a file goes through once, so every channel gets the same status, approval and audit trail.En lugar de diseñar cada servicio como una función aparte, diseñé una vez las etapas por las que pasa un archivo, para que todos los canales tengan el mismo estatus, aprobación y registro de auditoría.
  3. 03Built on the entitlement moduleConstruido sobre el módulo de permisosScotiaConnect’s strongest feature already controls who can do what. Every channel now runs through it: the client’s admin sets the approvers and the creator, authorizer and auditor roles in one place.La mayor fortaleza de ScotiaConnect ya controla quién puede hacer qué. Ahora todos los canales pasan por ahí: el administrador del cliente define en un solo lugar a los aprobadores y los roles de creador, autorizador y auditor.

What testing changedLo que cambió con las pruebas

An A/B test of two prototypes with 45 corporate clients (5 moderated sessions, 40 unmoderated) in the US, Canada, Mexico and Chile. Between the first and the second, editing a file moved from a confusing multiple selection to an action on each row, and each file got a clear status instead of a generic “received”.Una prueba A/B de dos prototipos con 45 clientes corporativos (5 sesiones moderadas y 40 no moderadas) en Estados Unidos, Canadá, México y Chile. Del primero al segundo, editar un archivo pasó de una selección múltiple confusa a una acción en cada fila, y cada archivo obtuvo un estatus claro en lugar de un “recibido” genérico.

Key decisionsDecisiones clave

  1. 01Speak the product team’s languageHablar el idioma del equipo de productoThe phases are named Explore, Shape, Build and Learn to match how product plans, so design work fits into their planning instead of running beside it.Las fases se llaman Explore, Shape, Build y Learn como las nombra producto, para que el diseño entre en su planeación en lugar de correr en paralelo.
  2. 02Every phase ends with something concreteCada fase termina en algo concretoEach phase has its deliverables and who takes part, from a problem brief to UX acceptance criteria. Accessibility acceptance criteria live inside the user stories.Cada fase tiene sus entregables y quién participa, desde el brief del problema hasta los criterios de aceptación UX. Los criterios de accesibilidad viven dentro de las historias de usuario.
  3. 03Measure design, not only ship itMedir el diseño, no solo entregarloNine design KPIs, from state coverage (empty, error, loading) to WCAG AA compliance, design-system deviation and fewer UI tickets.Nueve KPI de diseño, desde la cobertura de estados (vacío, error, carga) hasta el cumplimiento WCAG AA, la desviación del design system y menos tickets de UI.
